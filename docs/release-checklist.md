# Shared Memory release checklist

Every product change must be reflected on the public Shared Memory product page. A release is fully complete only after its artifacts and the live product page have been verified.

- [ ] Confirm the reviewed commit, passing checks, exact version, release tag, published assets and artifact digests. Read back the published GitHub release and MCP Registry entry separately; distinguish their availability from any other package registry.
- [ ] Synchronize [the product page release history](https://evergences.com/products/shared-memory/#release-history) with the exact released version and publication date. Use the GitHub release's `publishedAt` date in UTC, rather than the PR or commit date. Describe the shipped factual scope and material limitations, and link to the matching immutable GitHub release/tag and versioned documentation or implementation PR.
- [ ] Coordinate the website update with the thread or maintainer already responsible for it. Update any current-version or capability claims affected by the change as well as the release-history entry. Use the existing website review/deployment process; avoid concurrent site edits. Do not claim the page was updated merely because an update was requested or a deployment started.
- [ ] After deployment, fetch the live public URL and verify the `release-history` anchor, version, date, factual scope and source-link targets. An HTTP 200 alone is insufficient: read the actual served content and check it against the published release. Confirm that the versioned source links resolve to the intended release.
- [ ] Report a release as fully complete only after these checks pass. Include the GitHub release, registry result and live release-history URL in the completion report. If the website is pending or mismatched, report the artifacts as published and the product-page update as outstanding, naming the owner and exact remaining verification.

For v1.1.6 (published October 19, 2026 UTC), the factual scope is optional external runtime-state references with conservative compatibility decisions and evidence-only fallback. It does not load runtime snapshots, resume models, restore action authorization or establish inference speedups. The release source is [v1.1.6](https://github.com/seanmeverett/shared-memory-mcp/releases/tag/v1.1.6), with [versioned integration documentation](https://github.com/seanmeverett/shared-memory-mcp/blob/v1.1.6/docs/workflow-integration.md) and [implementation PR #6](https://github.com/seanmeverett/shared-memory-mcp/pull/6).

This checklist is repository maintenance documentation outside the release bundle's explicit file allowlist. Updating it does not require replacing an immutable artifact, changing its recorded digest or publishing another product version.
